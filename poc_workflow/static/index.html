Cơ chế Runtime & Bảo mật

Hệ thống kết hợp giữa giao diện quản trị gọn nhẹ và các tác nhân AI chạy ngầm. Khi người dùng đặt câu hỏi:

  • Application Backend: Tiếp nhận yêu cầu tại cổng :8088.
  • Bảo mật Ranh giới: Giao tiếp giữa Vercel UI và local server qua Tunnel có xác thực header X-KB-Token. Nếu token sai, hệ thống lập tức ở chế độ fail-closed.
  • Tầng Truy xuất (Retrieval): Chỉ lấy dữ liệu từ các tài liệu có trạng thái active trong manifest/records.json.
  • Tích hợp LLM Gateway: Gọi LLM thông qua gateway ở cổng :3001 để tổng hợp câu trả lời từ context chunks, đảm bảo dữ liệu không bị rò rỉ.

Luồng Ingestion & Số hóa

Vòng đời xử lý và chuẩn hóa tài liệu đầu vào trước khi được lập chỉ mục:

  • Intake: File được nạp vào inbox/ (hoặc qua UI), AI Agent phân loại sơ bộ (procedure, vendor_document, form_checklist, faq_troubleshooting).
  • Chuyển đổi MinerU: Chuyển đổi PDF, XLSX, DOCX thô thành Markdown tại normalized/ và trích xuất cấu trúc bảng biểu, hình ảnh, model/middle layout JSON.
  • Kiểm định QA: Chạy qa_source_output() đánh giá mojibake, độ phủ từ vựng, tính trích xuất bước thủ tục. Nếu lỗi, chuyển sang trạng thái sửa đổi.
  • Đóng gói RAG-Ready: Tạo manifest liên kết dòng Markdown với bounding boxes/tọa độ trang MinerU và lưu bản ghi dưới dạng pending_review.

Xử lý Hỏi-Đáp & Định tuyến

Các bước xử lý tuần tự khi nhận được truy vấn từ người dùng:

  • Nhận diện Ý đồ & Style: Xác định style hiển thị câu hỏi (brief, steps, checklist, workflow) và phân tích phòng ban/danh mục mục tiêu.
  • Bộ lọc Ngoài Phạm vi: Kiểm tra câu hỏi ngoài phạm vi nghiệp vụ kỹ thuật thông qua heuristic bộ lọc is_out_of_scope_query() để chặn câu hỏi rác.
  • Catalog Fallback: Nếu hỏi danh sách quy trình, hệ thống dùng build_catalog_answer() trả về danh sách có định dạng không cần đi qua LLM.
  • Định tuyến (Routing): Định tuyến giữa RAGFlow API (HTTP REST) hoặc Local Search Index (BM25 + Heuristics cục bộ).

Thuật toán & Chấm điểm RAG

Cơ chế tìm kiếm cục bộ và hiệu chỉnh điểm số thông minh của LocalRagIndex.search():

  • Điểm số thô: (Title_overlap * 4) + Text_overlap dựa trên Meaningful Terms của truy vấn.
  • Mã tài liệu Boost (+250): Ưu tiên tuyệt đối khi truy vấn khớp chính xác mã hiển thị (như PD-TECH-A-01).
  • Hiệu chỉnh ý đồ: Boost mạnh khi khớp ý định tìm kiếm (như mục đích, bảo dưỡng, CCDC, chứng chỉ, biểu mẫu, hồ sơ) từ +40 đến +85 điểm.
  • Phạt nhiễu & Lịch sử sửa đổi (-30): Giảm điểm các chunk chứa bảng chỉnh sửa, thông tin rác hoặc text OCR chất lượng thấp.
  • Lọc tự tin & Focus: Chỉ giữ các chunk có điểm >= 8 và tập trung kết quả vào tài liệu có độ khớp cao nhất để tránh trộn lẫn nội dung.

Luồng Vận Hành Tác Nhân AI

Mô hình trạng thái và các tác nhân tự động chạy ngầm trong hệ thống:

  • Quản lý Handoff Contract: Hệ thống lưu nhật ký chuyển tiếp tại handoffs.jsonl, đảm bảo tính tuần tự nghiêm ngặt (plan -> convert -> audit -> index -> evolve).
  • Tự Động Sửa Lỗi (Repair Loop): Nếu bước audit bị gắn mác needs_repair, tác nhân sửa lỗi tự động được kích hoạt để khắc phục Markdown lỗi.
  • Human Review Gate: Sau khi đóng gói RAG-ready, tài liệu ở trạng thái pending_review chờ Quản trị viên duyệt checklist nghiệp vụ trên Dashboard để đổi thành active.
  • Tái tạo chỉ mục: Phê duyệt kích hoạt approve_record(), lưu trữ phiên bản cũ (archived/retired) và tái tạo cơ sở dữ liệu tìm kiếm cục bộ.

Act as an expert AI documentation architect and senior codebase auditor.

# Objective
Scan the current codebase structure, system dependencies, configuration settings, and database schemas. Update the project's visual architecture dashboard, text explanations, and the architecture changelog (docs/architecture-changelog.md) to accurately reflect the changes.

# Context
The project is a Chatbot Workflow with document processing (Intake, HyperScribeModel normalization, Quality Governance, Knowledge Retrieval, and LLM Orchestration). The frontend is an Application API + Vanilla CSS HTML dashboard featuring Mermaid.js diagrams, a Bento Grid system showing component statuses, and documentation detailing ports and directories.

# Instructions
Follow these steps systematically:
1. **Research & Scan**: Inspect critical backend files in the workflow package (specifically `webapp.py`, `pipeline.py`, `database.py`, `quality_gate.py`, `converter.py`) to discover changes in:
   - Port configurations and default API endpoints (Application API: :8088, HyperScribeModel: :8010, LLM Proxy: :3001, KnowledgeCore: :9380).
   - Active ingestion stages, quality checks, folder definitions, or database schema models.
2. **Synchronize Code & UI**: If differences are found between current codebase settings and the UI representation:
   - Modify the `MERMAID_DIAGRAMS` dictionary in `static/app.js` (maintain strict Mermaid syntax, escape special characters, use matching status styling).
   - Update textual descriptions in the split panes under `
` in `static/index.html`.
   - Update metadata labels or names in the Bento Grid (`.bento-grid` in `index.html`) if the underlying modules/ports changed.
3. **Maintain Architecture Changelog**:
   - Write or update `docs/architecture-changelog.md`.
   - Maintain a version history table using GFM format:
     | Version | Date (YYYY-MM-DD) | Description of Changes | Affected Components | Author |
   - Document any deprecations, environment variable changes, or new ports.
4. **Verification**:
   - Run `pytest` to ensure all system tests pass.
   - Verify the Mermaid diagrams compile correctly by inspecting the browser logs.

# Constraints & Rules
- Do NOT use external CSS frameworks. Only utilize standard design tokens from `styles.css`.
- Ensure all Mermaid diagrams are properly escaped. Do not use raw "&" in node labels (use "và" or "and").
- Retain the exact visual theme and premium glassmorphic style.
- Only modify architecture-related files and documentation.

# Output Format
Respond with a clear list of files scanned, details of changes identified, and a diff of modifications applied to app.js, index.html, and docs/architecture-changelog.md.
